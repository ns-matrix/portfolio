Project deep dive / 3D driving simulation

Rickshaw Rush
Real City Drive.

The current playable build combines MapLibre street tiles with a Three.js procedural auto-rickshaw, road-following OSRM routes, area selection, keyboard/touch driving, passenger pickup/drop-off missions, and speed/distance/fare indicators. It supports map zoom, camera tilt/follow, reset, a service-worker map-tile download/cache flow, and a local practice-mode fallback when map services fail. The separate data/mumbai-route-areas.json dataset documents waypoint loops for Powai/IIT Bombay/Chandivali, Andheri East/Marol/MIDC, and Marine Drive/Churchgate/Oval Maidan, but the browser mission code does not yet load it. A separate Python/Ursina prototype is also included.

Inspect source ↗
01 / Road-aware simulationSelect Powai, Andheri East, or Marine Drive. The browser version requests driving routes from OSRM and can use a local practice route when routing fails.
02 / 3D vehicle and controlsThree.js renders a procedural auto-rickshaw, with an optional GLB model loader. Keyboard and touch controls support steering, throttle, and braking.
03 / Missions, offline resilience and route dataPassenger pickup/drop-off missions feed fare scoring and the HUD. A service worker can cache selected-area map tiles, while a practice-mode fallback keeps basic driving available if live map services fail. The separate Mumbai waypoint JSON is documented but not yet loaded by browser missions; the Python/Ursina prototype uses Overpass and OSRM.

DOCUMENTED STACK: HTML · JavaScript · Three.js · MapLibre GL JS · Python / Ursina · OpenStreetMap · OSRM

Live browser demo verified on 29 October 2026 (HTTP 200): Play Rickshaw Rush ↗. Fresh street tiles and OSRM routing need internet; cached tiles and practice mode are resilience features, not a production offline navigation guarantee.

How the work is approached

From idea to useful software.

Product thinking matters as much as implementation.

01 / FRAME

Define the problem

Identify the user, the task that needs to improve, and what a useful outcome looks like.

02 / MODEL

Choose the right tools

Match algorithms, data models, infrastructure, and UI patterns to the problem.

03 / BUILD

Make it usable

Turn core functionality into interfaces, workflows, and explainable results.

04 / REFINE

Review and improve

Document setup, validate edge cases, and iterate based on what the system reveals.
