01 / Context

The problem and the intent

Make code feedback easier to inspect, understand, and act on.

Problem

Validation output needs actionable context.

Developers may need syntax feedback, security observations, explanations, suggested changes, or a record of previous validations—not just a pass/fail signal.

Approach

Use deterministic checks as the baseline.

The documented design runs language detection and deterministic validation first, then uses a local Ollama model for contextual tasks. The model supports the validation engine rather than replacing every check.

02 / Capabilities

A focused code-review workflow

Capabilities summarized from the repository README.

01 / VALIDATE

Run baseline checks

Detect language and run syntax, static, and security-oriented checks before model analysis.

02 / EXPLAIN

Understand the issue

Focused LLM actions cover explanations, bug investigation, security review, optimization, test drafting, and documentation.

03 / FIX

Inspect suggested changes

Request corrected code and a diff so proposed edits can be reviewed.

04 / FORMAT

Keep formatting deterministic

Formatting is documented as a deterministic capability, separate from model suggestions.

05 / HISTORY

Review past validations

Validation history can be stored using PostgreSQL or Supabase, depending on configuration.

06 / DASHBOARD

See recent activity

Dashboard views include scores, charts, and recent activity as documented in the README.

Operational note

Deterministic checks can still run if Ollama is unavailable; model-powered actions require Ollama to be running and configured.

03 / Engineering

Separate checks from reasoning

The model has a supporting role in a broader validation pipeline.

Request flow

From editor to report

  • React, Monaco, and Tailwind provide the browser UI.
  • Frontend requests are routed to a FastAPI backend.
  • Language detection and static/security validators establish a baseline.
  • A validation orchestrator can call Ollama for contextual analysis.
  • PostgreSQL or Supabase can store validation history.
Technology choices

Each layer has a defined job.

The editor handles code input; the API coordinates validation; deterministic checks establish a baseline; Ollama adds contextual analysis; and the database stores history.

Before running

Documented prerequisites: Python 3.11+, Node.js 18+ (20 LTS recommended), PostgreSQL or Supabase, and Ollama for model-powered actions. Configure backend/.env and never commit secrets.

Local URLs: frontend http://localhost:5173, backend health http://localhost:8001/api/health, and API docs http://localhost:8001/docs.
